## 問題別

### A・B

- **A**：`o` を数えて偶奇を判定する、公式と同じ方針です。O(|S|)、`|S| ≤ 10`。修正は不要です。
- **B**：縦5本・横5本・斜め2本の計12本について、空きマスの最小値を求めています。[公式解説](https://atcoder.jp/contests/abc482/editorial/28013)と同じで、固定サイズなので O(1)。12本を漏れなく扱えています。

### C — Band Count

**アルゴリズム：ソート、二分探索。**

行順・列順に並べた配列で、「左端以上の最初の位置」と「右端より大きい最初の位置」の差を取っています。[公式解説](https://atcoder.jp/contests/abc482/editorial/28016)と同じ方針です。

良い点は、`>=` と `>` を使い分け、同じ行・列に複数の駒がある場合も正しく数えていることです。探索結果がないときの `|| N` も適切です。O((N+Q) log N) で、`N,Q ≤ 3×10^5` に対応します。

公式は行番号だけ・列番号だけの配列を持っています。今のコードは座標の組を保持していますが、正しさに問題はありません。簡潔にするなら、必要な座標だけを取り出す程度です。

### D — Wannabe Zombie

**アルゴリズム：場合分け、最初に感染する隣人に注目する。**

[あなたのコード](d/main.rb)の式は、[公式解説](https://atcoder.jp/contests/abc482/editorial/28014)と一致しています。全体 O(N) で、`N ≤ 2×10^5` に十分です。`N=1`、`N=2` の境界ケースも確認しました。

この問題で残しておきたい考察は、**最初に左右どちらの隣人をゾンビにするかを決めれば、その後は両端まで感染が届く時間だけ見ればよい**という点です。

たとえば右隣を先に感染させる場合、最終的な必要時間は、0-indexed で

`max((X[-1] - X[i]) / 2, (X[i+1] - X[0]) / 2)`

となります。左隣を先にする場合も対称で、2通りの小さい方が答えです。あなたの `ans1`・`ans2` はそのままこの式になっています。

実装上の大きな改善点はありません。保存時刻の間隔からは C→D に約32.5分使ったと推定できますが、考察・実装・デバッグの内訳は提出履歴なしでは判断できません。

### E — Diameter Endpoint Colors

**アルゴリズム：あなたは木の直径・DFS・ペア列挙。公式は木の直径・木の中心・色ごとの数え上げです。**

今のコードは、頂点0から最も遠い頂点をすべて集め、それぞれから再度 DFS して最遠頂点との組を `Set` に保存し、最後に同色の組を数えています。

「最遠頂点を使って直径の端点を探す」という入口は合っています。ただし、独立した問題が2つあります。

**1. 初期化で「距離」と「頂点番号」が逆になっています。**

[コード](e/main.rb)の2回目の探索の初期化（ヘッダー追記前の68行目）の

```ruby
ranks[start] << 0
```

は、「距離 `start` のところに頂点0がある」という意味になります。本来は次の対応です。

```ruby
ranks[0] << start
```

最初の探索は `start=0` なので誤りが表面化しません。2回目以降、開始頂点の番号が直径と一致すると、頂点0が最遠頂点に紛れ込みます。

実際に、次の入力で確認しました。

```text
3
1 2
1 3
1 1 1
```

直径は2で、条件を満たす組は頂点2と3だけなので、正解は **1**。現在のコードは **2** を出します。

一時ファイルで初期化を直すと、この反例とサンプル3件は通りました。ただし、これだけでは次の問題が残ります。

**2. 端点候補ごとの DFS とペア保存が、最悪 O(N²) です。**

頂点1が中心で、残りがすべて葉の星形の木を考えると、最初の探索の最遠頂点は `N-1` 個あります。

- それぞれから木全体を DFS：O(N²) 時間。
- 葉どうしのペアを `Set` に保存：O(N²) 領域。

`N=2×10^5` では葉のペアが約200億組あるため、個別に列挙する方針では間に合いません。色の判定を前に移しても、全頂点が同色なら解消しません。

**気づきたかったポイントは、「直径の端点ペアは大量にあっても、そのパスはすべて木の中心を通る」です。**

[公式解説](https://atcoder.jp/contests/abc482/editorial/28018)では、まず探索2回で直径を1本求め、その中央を使って数えます。

- **直径が偶数 `D=2h` の場合**  
  中心は1頂点。中心から距離 `h` にある頂点どうしで、**別の枝に属するもの**だけが直径の両端になります。色 `c` の総数を `total[c]`、枝 `b` 内の数を `cnt[b][c]` とすると、答えは  
  `Σc total[c] * (total[c]-1) / 2 − Σb,c cnt[b][c] * (cnt[b][c]-1) / 2`。
- **直径が奇数 `D=2h+1` の場合**  
  中央の辺を切って左右に分けます。それぞれ中央の頂点から距離 `h` にある頂点を色別に数え、`Σc left[c] * right[c]` が答えです。

どちらも各頂点を定数回処理する **O(N)** の解法です。

偶数の場合は、枝を1本ずつ処理し、「それまでの枝にあった同色頂点の数」を加算する方法も使えます。このときは、**枝の集計が終わってから全体のカウンタに加える**ことで、同じ枝のペアを数えずに済みます。

手持ちの知識との距離は近いです。[ABC222 F](../abc222/f/main.rb)にも直径の端点を探す処理があります。今回加えるべき知識は、**直径の中心で木を分ければ、端点の組を個数の積で数えられる**という性質です。高度なデータ構造は必要ありません。

### F — Mod M Divisor

**公式のアルゴリズム：素因数分解、01-BFS、状態をグラフの頂点とみなす。**

最初の観察は、**`N^t` の約数は、`N` の約数を `t` 個掛け合わせて作れる**ことです。

そこで余りを頂点にし、`N` の約数 `d` を掛ける操作を `r → r*d % M` という辺にすると、最小回数の問題になります。ただし、全約数について辺を作ると O(M×約数の個数) で重くなります。

[公式解説](https://atcoder.jp/contests/abc482/editorial/28017)は、ここを素因数ごとの段階に分解します。

1. `N = p0^a0 × p1^a1 × …` と素因数分解する。
2. 状態を「現在の余り」と「次に処理する素因数」にする。
3. 各段階で、その素因数を0回〜`ai` 回掛ける。
4. 素因数を一巡すると「N の約数を1個掛けた」ことになるので、一巡の開始だけコスト1、残りは0にする。

これで 01-BFS が使えます。計算量は O(√N + M log N)。なお `t` は正整数なので、初期状態の余り `1 % M` も答えは0ではなく1です。`N=1` も別扱いになります。

ABC481 D の振り返りに出てきた 01-BFS とつながる問題ですが、今回の難所は **約数を掛ける操作を、素因数ごとの段階へ分解すること**です。E の次に取り組む候補です。

### G — Degree Harmony 2

**公式のアルゴリズム：線形マトロイドパリティ、乱択、行列の階数。**

次数制限付きで辺を最大数選ぶ問題を、辺ごとのベクトル対の選択に変換します。[公式解説](https://atcoder.jp/contests/abc482/editorial/27996)では、乱数を使って作る行列の階数の半分から答えを得ます。主要部分は O((ΣA)³)、`ΣA ≤ 500` です。

E・F と比べて新しく学ぶ理論が大きいため、今回の復習では優先度を下げてよいと思います。

## ABC481・480 から見た今回の学び

保存時刻からの推定では、Bまで約5.4分、Cまで約17.5分なので、ABC480・481 のようにBで長く停滞した形ではありません。一方、Eが本番で通ったかどうかは未確認です。

前回のEは「方針は合っていて、比較の符号や精度が問題」でした。今回は、初期化の誤りに加えて **ペアを列挙すること自体が制約に合わない**ため、中心を使う数え上げへの変更が必要です。

今回残したい学びは3つです。

1. **木で探索を何回も回すなら、星形で回数を見積もる。** 最遠頂点の数は O(N) になり得る。
2. **答えが O(N²) 個あっても、求めるのが個数だけなら集計で数える。** 今回は色別の個数の積・組合せに置き換える。
3. **始点0で動いた処理を他の始点に使い回すときは、初期化を確認する。** `ranks[距離] << 頂点番号` のように、添字と値の意味を固定する。

次にやることは、まず **Eを木の中心からの数え上げで解き直す**ことです。奇数・偶数の直径、星形、全頂点が同色のケースを確認し、その後Fに進むのがよい順序です。
