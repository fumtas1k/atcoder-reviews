### D - Back and Forth Distance(AC 24.2 分)
**アルゴリズム**: 最初の一手で場合分け、累積 min(あなたはセグメント木で区間 min)

**あなたの解法**: `s < t` なら `min(R[s], L[s] + (s より左の R の最小))`、逆向きは対称です。`O((N + Q) log N)` で、`N = Q = 3×10^5` なので問題ありません。サンプルが 1 件しかないので、愚直解(ワーシャル–フロイド法)とのランダムテストを 300 件流し、すべて一致しました。

**良いところ**
- `L` の先頭と `R` の末尾に `INF` を入れて、端のマスの場合分けを消しています。公式の実装例は `if (s > 0)` で分岐しています。

**改善できるところ**
- 区間 min を取る範囲は常に「先頭から `s` の手前まで」か「`s` の次から末尾まで」です。累積 min の配列を 2 本作れば足り、セグメント木は要りません。

**公式解説との違い**: 式は同じで、公式は累積 min でクエリあたり `O(1)` です。

### E - Cut and Add(着手・未提出 / 最終保存 99.7 分)
**アルゴリズム**: あなた: 木の重心 / 公式: 部分木への加算を根から流す(木の上のいもす法)

**どこまで合っていたか**: 方針は合っていて、あと一歩でした。手元のコードは `dfs3` が書きかけ(`temp[]` で実行時エラー)で、出力もありません。

- 重心を求めて根にする `dfs1`、`dfs2` は正しく書けています。
- 重心を根にすると、どの辺を切っても子側の部分木は `N / 2` 以下です。だから大きいのは必ず親側で、78 行目からの `size_a > size_b` の分岐は要りません。
- その分岐の `size_a = N - children[a]` は誤りです。親側の成分の大きさは `N - children[b]` です。
- 詰まった原因は、加算を親 `a` の側に `temp[a][0] += i` と記録したことだと見ています(推定)。親に置くと、どの子の部分木を除くのかが後から分かりません。

**最小の直し方**: 辺 `i` で加算されないのは、子側の部分木の頂点だけです。つまり頂点 `v` が辺 `i` の加算を逃すのは、辺 `i` が根から `v` へのパス上にあるときだけです。

`x[v] = (全辺の番号の和 N(N-1)/2) - (重心から v までのパス上の辺番号の和)`

隣接リストに辺番号を持たせれば、`dfs2` 以降は次の DFS 1 本になります。サンプル 3 件と、愚直解とのランダムテスト 300 件で一致を確認しました。

```ruby
# edges[a] << [b, i] の形で辺番号 i（1 始まり）を持たせる
ans = [0] * N
dfs2 = ->(pos, pre = -1, cut = 0) do
  ans[pos] = N * (N - 1) / 2 - cut
  edges[pos].each do |nex, i|
    next if nex == pre
    dfs2.(nex, pos, cut + i)
  end
end
dfs2.(centroid)
puts ans.join(" ")
```

**公式解説との違い**: 公式は重心を使わず、頂点 1 を根にします。子側が大きい辺は「子の部分木に `+i`」、親側が大きい辺は「全体に `+i`、子の部分木に `-i`」として、最後に根から葉へ値を流します。あなたの重心の方針は後者の場合だけになるので、式が 1 本で済みます。公式の方針は、重心という性質が使えない類題にもそのまま使えます。

**気づきたかったポイント**
- 「部分木の外側全部に足す」は「全体に足して、部分木から引く」と同じ。
- 部分木への加算は、その部分木の根(子側の頂点)に置いて、最後に上から下へ流す。

**手持ちの知識との距離**: 新しい道具はありません。重心も部分木サイズも自力で書けていて、足りなかったのは上の言い換え 1 つです。

**補足(再帰の深さ)**: パス状の木(`N = 199999`)を手元で流すと、ラムダ再帰は深さ約 7000 で `SystemStackError` になりました。ジャッジ上で落ちるかは未確認です。公式の実装例は BFS 順の配列を前後から走査していて、再帰を使いません。

### F - Narrow Passage(未着手)
**アルゴリズム**: 公式: 転倒数、フェニック木、条件の言い換え(空きマスも要素とみなす)

**解法の骨子**
1. 空きマスも「区別のない人」とみなすと、操作は数直線全体の列に対する隣接 swap です。答えは `S` の並びを `T` の並びにする転倒数になります。
2. 空きマス同士は順序を入れ替えないので、寄与は 0 です。
3. 人同士の寄与は、`S` の昇順に人を並べたときの、`T` の順位の転倒数です。
4. 人 `x` と空きマスの寄与は、「`S[x]` より左の空きマスの数」と「`T[x]` より左の空きマスの数」の差の絶対値です。前者は `S[x] - (S の中での順位)`、後者は `T[x] - (T の中での順位)` です(順位は 0 始まり)。
5. 3 と 4 の合計が答えで、`O(N log N)` です。

この方針で書いたコードがサンプル 3 件を通ることを確かめました(ランダムテストはしていません)。

**気づきたかったポイント**: 「移動先に人がいたら入れ替わる」と「空きマスへ動く」は、空きマスを要素とみなすと同じ隣接 swap です。隣接 swap の最小回数は転倒数、という典型に落ちます。

**手持ちの知識との距離**: 転倒数は `abc396/f` と `abc441/e` で扱っています。距離があるのは、空きマスを要素とみなす見方と、長さ 10^9 の列の転倒数を寄与に分ける部分です。

### G - Tuning(未着手・射程外)
**アルゴリズム**: 公式: 条件の言い換え(全点を原点を通る 1 本の直線に乗せる)、重み付き中央値

直線の傾きを決めると、動かすのは x 方向だけか y 方向だけのどちらかが最適です。y 方向だけなら `|A[i] * x - B[i]|` の総和の最小化で、`B[i] / A[i]` を重み `A[i]` で見た中央値が最適です。`A` と `B` を入れ替えて 2 回解きます。今は追わなくてよい問題です。
