### C - Sort Subarray（diff 426 / AC 17.0 分）
**アルゴリズム**: 条件の言い換え（ソート後の列と比べ、食い違う範囲が長さ K に収まるか）

**あなたの解法**: `A` と `A.sort` を前から比べ、最初の食い違いから `K` 個を操作区間とみなし、その後ろに食い違いが残れば No。`O(N log N)` で `N = 2×10^5` なので問題ありません。愚直解とのランダムテスト 300 件で一致しました。

**良いところ**
- 「区間の外は操作で変わらないので、最初からソート後と一致している必要がある」という必要十分条件に 8 分で届いています。公式の判定と同じです。

**改善できるところ**
- `unmatch` / `cnt` / `ans` の 3 つの状態で分岐が 3 段になっています。食い違う添字の両端だけ見れば状態が要りません（サンプル 3 件、ランダムテスト 300 件で確認済み）。

  ```ruby
  sorted = A.sort
  diff = (0...N).select { A[it] != sorted[it] }
  puts diff.empty? || diff[-1] - diff[0] < K ? "Yes" : "No"
  ```

**公式解説との違い**: 判定は同じです。公式の実装例はソートせず、左からの最大値と右からの最小値で両端を求めて `O(N)` にしています。この制約ではソート版で十分です。

**別解**: ユーザ解説（Tamiji さん）は、区間の外が昇順であることと、区間の最小値・最大値が両隣と矛盾しないことを、セグメント木かスライド最小値で調べます。区間の位置を全部試す形なので、「操作する場所が決め打ちできない」類題ではこちらが使えます。

### D - Range Set Insertion Query（diff 729 / AC 33.5 分）
**アルゴリズム**: イベントソート、優先度付きキュー（公式はイベントソート + カウンタ配列）

**あなたの解法**: 位置を左から進め、`L` が現在位置の操作を取り込み、`R` が過ぎた操作を最小ヒープから捨てる。重なっている `X` の個数を `group` で持ち、`group.size` を答えにする。`O(Q log Q + N)` で `N = Q = 2×10^5` なので問題ありません。ランダムテスト 300 件で愚直解と一致しました。

**良いところ**
- 個数が 0 になったキーを `delete` しているので、種類数を別の変数で増減させずに `group.size` をそのまま答えにできています。数え間違いが入りにくい形です。
- 「位置を時刻とみなし、区間を開始と終了に分ける」という見方が、公式の読み替えと同じです。

**改善できるところ**
- 優先度付きキューは要りません。ヒープが必要なのは終了時刻が後から決まるときで、この問題は終了位置 `R + 1` が最初から分かっています。位置ごとのバケツに入れれば、ソートもヒープもなしで `O(N + Q)` になります（サンプル 2 件、ランダムテスト 300 件で確認済み）。

  ```ruby
  add = Array.new(N + 1) { [] }
  del = Array.new(N + 1) { [] }
  Q.times do
    l, r, x = gets.split.map(&:to_i)
    add[l - 1] << x
    del[r] << x
  end
  group = Hash.new(0)
  ans = Array.new(N) do |i|
    del[i].each { group.delete(it) if (group[it] -= 1).zero? }
    add[i].each { group[it] += 1 }
    group.size
  end
  puts ans.join(" ")
  ```

  今の解法が遅いという話ではありません。C から D まで 16.5 分かかっているので、部品を 1 つ減らせる形を知っておくと次は短くなる、という趣旨です。

**公式解説との違い**: 公式は（位置, X, ±1）のイベントを 1 本の配列にしてソートし、カウンタが 0 と 1 の間を行き来したときに答えを増減します。あなたの解法は開始だけソートし、終了をヒープに任せています。考え方は同じです。

**別解**: ユーザ解説（seekworser さん）は、セグメント木の要領で各操作を log 個の区間に配り、根から DFS しながら集合を巻き戻す方法です。この問題には重いですが、「区間に載せたものを各点で集計する」一般形として使えます。

### E - lt and le（diff 1376 / 終了 6.3 分後に AC）
**アルゴリズム**: 強連結成分分解、トポロジカルソート（公式と同じ）

**あなたの解法**: `t` によらず `u -> v` の辺を張って SCC を取り、成分のトポロジカル順の番号を答えにする。`t == 1` の辺の両端が同じ成分なら No。`O(N + Q)` です。

**良いところ**
- グラフを作る段階では `<` と `<=` を区別せず、`<` の検査を最後の `TUV.any?` の 1 か所に分けています。公式の実装例と同じ構成です。
- 成分数は `N` 以下なので、値が 1 以上 `N` 以下という条件のための処理を足していないのは正しい判断です。

**公式解説との違い**: 同じ方針で、コードの形もほぼ一致しています。

**何に時間を使ったか**: D を通してから終了まで 66.5 分あり、提出は終了後の 1 回だけで不正解はありません。コードは 19 行で公式と同じ形なので、時間を使ったのは実装より方針を立てる段階だと見ています。ここは推定です。`ac-library-rb/scc` は `practice2/g`、`abc399/e`、`awc0030/d` で使っているので、道具は持っていました。

**気づきたかったポイント**: 「`A[u] <= A[v]` の辺をたどって一周できるなら、その輪の上は全部等しい」。等号つきの不等式が辺で与えられたら、まず「閉路の上は等しいので SCC で 1 点に潰す」を候補に上げます。`<` だけなら閉路があれば即 No でトポロジカルソートで済み、`<=` が混ざると SCC が要る、という対比で覚えておくと次は早く出ます。

### F - Min-First Search（diff 1588 / 未着手）
**アルゴリズム**: 公式: 数え上げ、単調スタック（直前にある自分より大きい要素）

**解法の骨子**（位置は 0 始まり）
1. 頂点 1 を根にして、木を「各頂点の親を決めたもの」と見る。頂点が `S` に入るのは、親が取り出された直後。
2. `Q[i]` の親が位置 `j` にあるとする。`Q[i]` は位置 `j` の直後から `S` にいて、位置 `i` で初めて最小値として出る。だから位置 `j+1 .. i-1` で出た値は、すべて `Q[i]` より小さい必要がある。
3. `i` より前で `Q[m] > Q[i]` となる最後の位置を `m` とすると、親の候補は位置 `m .. i-1` の `i - m` 個。そのような `m` がなければ、前にある `i` 個すべて。
4. 候補数は他の頂点の選び方に依存しないので、答えは各 `i` の候補数の積（mod 998244353）。
5. `m` は単調スタックで全体 `O(N)`。`N = 2×10^5` なので問題ありません。

入力例 1 の `1 3 4 2 5` では候補数が 1, 2, 1, 4 で、積は 8 です。この方針で書いたコードがサンプル 3 件を通ることを確かめました。

**気づきたかったポイント**
- 「木を数える」を「根を決めて、頂点ごとに親を選ぶ」に直す。選択肢が頂点ごとに独立なら積で終わります。
- 入力例 1 で「4 の直後の 2 は、親が 4 しかありえない」と手で確かめると、「親と自分の間に自分より大きい値はない」という条件が見えます。

**手持ちの知識との距離**: 新しい道具はありません。直前のより大きい要素を単調スタックで求める処理は、`abc359/e` で同じ形（`stack.pop while !stack.empty? && stack[-1][1] < h`）を書いています。距離があるのは骨子 2 の言い換えだけです。レート + 400 の目安（1453）を少し超えますが、実装は 10 行ほどなので upsolve の第一候補です。

実装するときは、テンプレートの `MOD` が `10 ** 9 + 7` のままなので、998244353 に切り替えてください。

### G - Division Point Hull（diff 2582 / 未着手・射程外）
**アルゴリズム**: 公式: 凸包、分割統治法、Minkowski 和

添字を半分に分けると、左右にまたがる内分点の集合が「左半分の縮小」と「右半分の縮小」の Minkowski 和になります。凸包どうしの Minkowski 和は辺の偏角順マージで線形なので、全体 `O(N (log N)^2)` です。今は追わなくてよい問題です。
