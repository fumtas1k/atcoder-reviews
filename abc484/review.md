### C - Move One Card（終了後に AC、132.2 分）
**アルゴリズム**: 巡回シフトへの言い換え、一致する先頭と末尾を除く（公式と同じ）

**あなたの解法**: `A[i] != B[i]` になる最初の位置 `l` と最後の位置 `r` を求めます。そのうえで、`B[l..r]` が `A[l..r]` を左に 1 つ回したもの、または右に 1 つ回したものと一致するかを調べています。O(N) で、N = 2×10^5 に対して問題ありません。サンプル 4 件も通りました。

**良いところ**
- 前回 ABC483 の振り返りで挙げた「1 つだけ変える問題は、変わる部分と変わらない部分に分ける」が、そのまま使えています。一致する先頭と末尾を落として `[l, r]` だけを見るのは、公式解説と同じ発想です。
- `as1 = [*A[l + 1 .. r], A[l]]` と `as2 = [A[r], *A[l ... r]]` で、2 方向の回転を 1 行ずつで書いています。このほうが添字を 1 つずつずらして比べるより間違いにくく、`A == B` の場合も `l.nil?` で先に処理しています。

**公式解説との違い**: 公式と同じ方針です。公式は、「回す区間を `[l, r]` まで縮めても結果が変わらない」ことを証明しています。実際に操作される区間がもっと広い場合でも、外側の要素は値が等しく並んでいるので、狭めて構いません。あなたのコードはこの事実に頼っています。本番で 30 分かけても通せなかったのが、この点を確信できなかったからだとすれば、ここが詰まった場所の候補です。

**時間について**: B の AC から終了までの 29 分では通せず、AC は終了の 32 分後でした。1 回目の AC（2278 バイト）から 2 回目（1849 バイト）で短く書き直しています。1 回目の提出コードは取得できなかったので、本番中にどこで止まっていたかは未確認です。

### D - Move One Card Left（未着手・射程内）
**アルゴリズム**: 公式: 連想配列で出現回数を数える。数える対象を極小な操作に絞る

**解法の骨子**: C と同じく、操作は区間 `[l, r]` を右に 1 つ回すことです。同じ列が何度も数えられないように、両端が実際に変わる操作（`A[l] != A[r]` かつ `A[r] != A[r-1]`）だけを数えます。C で使った「変わる範囲を最小まで縮めてよい」という事実から、こうした操作は互いに違う列を作るので、組 `(l, r)` の個数がそのまま答えになります。`r` を左から順に動かし、`A[r] != A[r-1]` のときは「これまでに出た要素のうち `A[r]` と違うものの数」= `r - cnt[A[r]]` を足します。最後に、元の列の 1 通りを加えます。計算量は O(N) です。

**気づきたかったポイント**: 「操作の結果としてできる列の個数」を数える問題では、**同じ結果を生む操作の中から代表を 1 つ決めて、代表だけを数える**。ここでは、変わる範囲が最小になる操作を代表にしています。その代表がどんな操作かは C の考察でもう分かっているので、C と D は続けて考えることを前提にした出題です。

**手持ちの知識との距離**: 新しく覚える道具はありません。`Hash.new(0)` で出現回数を数えるだけです。

**模範解答**（サンプル 3 件と、愚直解とのランダムテスト 300 件で一致を確認）

```ruby
# -
# ABC484/D
# 数え上げ
# 同じ結果を生む操作から代表（極小な操作）を選んで数える
# 連想配列

N = gets.to_i
A = gets.split.map(&:to_i)

# cnt[x] := これまでに x が何回出たか
cnt = Hash.new(0)
ans = 1 # 操作しても列が変わらない場合（元の列そのもの）
A.each_with_index do |a, r|
  # 区間 [l, r] を右に回す操作が極小 <=> A[l] != A[r] かつ A[r-1] != A[r]
  ans += r - cnt[a] if r > 0 && a != A[r - 1]
  cnt[a] += 1
end

puts ans
```

### E - Subsegment Sum Finder（本番は未着手・終了後に WA → AC）
**アルゴリズム**: 公式: 累積和、座標圧縮、フェニック木。「L 以上 R 以下」を「X 以上」2 回の差に分ける

**解法の骨子**: 答えは「総和が L 以上」の個数から「総和が R+1 以上」の個数を引いたものです。累積和 `S` を使うと、「総和が X 以上」の個数は、各 `i` について `j < i` かつ `S[j] <= S[i] - X` を満たす `j` の個数の合計になります。`S` を座標圧縮し、出てきた `S[j]` をフェニック木に入れていけば、各 `i` について「`S[i] - X` 以下の個数」を O(log N) で数えられます。全体は O(N log N) で、N = 3×10^5 に対して余裕があります。

**気づきたかったポイント**: 区間の和の条件は、累積和の 2 点の差に書き直す。値が負にもなるので尺取り法は使えない、と気づけば、「前に出た値のうち〇〇以下の個数」を数える方針が候補に上がります。これは転倒数と同じ数え方です。

**手持ちの知識との距離**: `abc475/e` で使った「座標圧縮・フェニック木（順位を数えるための道具）」がそのまま使えます。新しいのは、上下限を 2 回の「以上」に分ける言い換えだけです。

**解き直し**: 累積和を座標圧縮し、各 `i` で `bsearch_index` を使って `[csum[i] - R, csum[i] - L]` に入る添字の範囲を求め、フェニック木の区間和で数えています。O(N log N) です。公式は「L 以上」と「R+1 以上」の 2 回に分けて引き算しますが、範囲を 1 回の区間和で数えるこの書き方でも同じ答えになり、走査も 1 回で済みます。

**不正解の原因**: 最初の版は、数える範囲が空のときに `next` で抜けていて、その後ろの `cnts.add(idx, 1)` まで飛ばしていました。そのため、後ろの `i` から見た「前に出た累積和」が欠けます。反例は `N = 2, L = R = 10, A = (100, 10)` で、正解 1 に対して 0 を出します。`ans += cnts.sum(l, r + 1) if l && l <= r` として `add` を毎回実行するように直すと、愚直解とのランダムテスト 300 件で一致し、提出も AC しました。

### F - Make them monochrome（未着手・射程内）
**アルゴリズム**: 公式: セグメント木（モノイドを自分で設計する）

**解法の骨子**: 区間の状態を 1 つの整数で表します。`-1` は「確定した値がない」、`-2` は「異なる値が 2 つある（不可能）」、それ以外の `x` は「確定値が x だけ」です。2 つの区間を合わせる演算は、片方が `-1` ならもう片方を返し、どちらかが `-2` か、値が違えば `-2`、同じならその値を返します。単位元は `-1` です。タイプ 1 は `set`、タイプ 2 は `prod` の結果が `-2` なら No です。

**気づきたかったポイント**: 1 点更新と区間の質問を交互にこなす問題は、「区間の情報を 2 つ合わせられるか」を先に考える。合わせ方が結合的に書ければ、セグメント木に載せられます。

**手持ちの知識との距離**: `awc0061/e` で `Segtree.new(n, 0) { |a, b| [a, b].max }` を使っています。違うのは、ブロックの中身を自分で場合分けして書く点だけです。
