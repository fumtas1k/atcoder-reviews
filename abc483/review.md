### C - Second Choice Election（AC 96.0 分 / 不正解 2）
**アルゴリズム**: あなた: 優先度付きキュー（古い要素は取り出すときに捨てる） / 公式: 差分に注目する、変わらない側は元の上位 2 人だけを見る

**あなたの解法**: 全員の基本票 `[first[k], k, INF]` をキューに入れます。候補者 `i` が辞退するたびに、`i` を第一希望にしていた人の第二希望 `k` について、票を足した `[first[k] + v, k, i]` を追加します。取り出すときは、タグ `cnt` を使って古い要素（`cnt < i`）を捨て、基本票（`cnt > i`）はあとで戻します。そのうえで、`i` 以外の最初の候補者を答えにしています。要素は合計 N + M 個で、各要素は捨てられるまでに高々数回しか取り出されません。全体で O((N + M) log(N + M))、N, M = 2×10^5 で問題ありません。小さいランダム入力 200 件で、愚直解との一致も確認しました。

**良いところ**
- 古い要素をキューから消さず、`cnt` のタグを見て取り出すときに捨てています。そのため、「辞退 1 回ごとにキューを作り直す」ことを避けられています。同点のとき番号の小さい方を優先する条件も、比較ブロックに正しく入っています。

**公式解説との違い（ここが今回の本題）**
公式の鍵は次の観察です。

> 候補者 k が辞退しても、票が**増える**のは k を第一希望にしていた人の第二希望の候補者だけ。それ以外の人の票は変わらないので、その中で勝てるのは「辞退前の 1 位 X と 2 位 Y」のどちらかだけ（k が X でも Y が残る）。

これに気づくと、比べる候補者は「X、Y、票が増えた人たち」の高々 N_k + 2 人です。N_k を全員で足すと M なので、全体は O(N + M) で済み、キューは要りません。あなたの解法は「票が変わる人をキューに入れ直す」ので、差分に注目しているところまでは同じです。違うのは**変わらない側を上位 2 人に絞る**一歩で、これがないために、古い要素を捨てる仕組みや基本票を戻す処理が必要になりました。実装量の差はそのぶんです。

公式の方針を Ruby で書くと次のとおりです。サンプルを通り、愚直解ともランダム入力 200 件で一致しました。

```ruby
N, M = gets.split.map(&:to_i)
AB = Array.new(M) { gets.split.map(&:to_i).map(&:pred) }
votes = [0] * N
moved = Array.new(N) { [] }
AB.each do |a, b|
  votes[a] += 1
  moved[a] << b
end
x, y = (0...N).min_by(2) { [-votes[it], it] }
ans = Array.new(N) do |k|
  moved[k].each { votes[it] += 1 }
  base = votes[k]
  votes[k] = -1
  win = (moved[k] + [x, y]).min_by { [-votes[it], it] }
  votes[k] = base
  moved[k].each { votes[it] -= 1 }
  win + 1
end
puts ans
```

なお、「1 つ取り除いたときの 1 位を、累積 1 位と 2 位で考える」という発想は、`awc0136/c`（建物を 1 つ取り除く問題）で `max1` と `max2` を持って解いています。同じ型です。

**不正解の原因**: 過去の提出コードは取得できなかったため（AtCoder の提出ページが 403 を返した）、原因は特定できていません。分かっているのはバイト数だけで、TLE 提出が 2092、WA 提出が 2206、AC 提出が 2195 です。WA から AC への変更は 11 バイトの差なので、比較やタグの条件を 1 か所直した程度と思われます。

### D - Glitchy Robot（着手・未提出）
**アルゴリズム**: 累積和、前後からの累積 max/min（公式）。考察の型は「1 か所だけ変えたときを全通り調べるなら、前と後ろから別々に前計算する」

**どこまで合っていたか**: 累積和 `sum` の最小値と最大値を更新しているので、「通る座標の個数 = 累積和の max − min + 1」という最初の観察はできています（`A` 自体の `min` と `max` は使いません）。反転しない場合の答えはこれで出ます。C を通した時点で残りは 4 分だったので、時間切れと見るのが妥当です。

**解法の骨子**: 累積和を S_0 = 0, S_1, …, S_N とします。A_k を反転すると、**S_k 以降がすべて一斉に `-2 * A[k]` ずれ**、それより前は変わりません。したがって、反転後の max は `max(S_0..S_(k-1) の max, S_k..S_N の max - 2*A[k])` で、min も同じ形です。前からの累積 max/min と後ろからの累積 max/min を作っておけば、各 k は O(1)、全体で O(N) です。この方針の Ruby 実装でサンプルを通し、愚直解とランダム入力 300 件で一致することを確かめました。

**気づきたかったポイント**: 「1 要素の符号を反転」は、累積和の上では「ある位置から後ろを丸ごと平行移動」と同じです。後ろ側をまとめて扱えると分かれば、前後からの累積が候補に上がります。

**手持ちの知識との距離**: 新しい道具は要りません。累積和と累積 max の組み合わせで届きます。

### E - Typo Pairs（未着手・射程内と推定）
**アルゴリズム**: 公式: 包除原理、連想配列

**解法の骨子**: M ≦ 6 が鍵です。2 か所を伏せ字にした文字列（伏せる位置の組は C(6,2) = 15 通り）で `tally` すると、ハミング距離 2 以下のペアが拾えます。ただし、距離 0 や 1 のペアは複数の組で重複して数えられます。そこで、1 か所を伏せたもの（M 通り）と、伏せないもので数えた個数を使って補正します。公式の式は `(M-1)(M-2)/2 × |A| − (M-2) × Σ|B_k| + Σ|C_kk'|` です（|A| は一致するペア数、|B_k| は k 文字目を伏せて一致するペア数、|C_kk'| は 2 か所を伏せて一致するペア数）。

**気づきたかったポイント**: 「M が 6 以下」という制約を見たら、伏せる位置を全探索する方針が候補に上がります。重複の係数は、距離 0・1・2 のペアが何回数えられるかを書き出せば逆算できます。

### F・G（射程外）
- **F**: `(x + A) mod B = x + A − B * floor((x + A) / B)` と書き直し、floor の値が変わる位置にいもす法で加算します。変わる位置の数は全体で約 INF/B の和なので、調和級数で抑えられます。
- **G**: P を固定し、期待値の線形性を使います。上位 K 人が重なる人数 r ごとに、二項係数で確率を出して足します。
